# Job Auto Apply

Портфолио-проект для поиска и предварительного отбора вакансий Junior Frontend (React/TypeScript, HTML/CSS) и отдельных фриланс-задач. Код собирает публичные объявления из нескольких источников, ранжирует их по заголовку, указанному стеку, уровню и совпадению с резюме, а затем отправляет отчёт в Telegram.

## Правила отбора

- Цель: стажировки (оплачиваемые и неоплачиваемые) и Junior / Junior+ позиции по Frontend / React / TypeScript; затем HTML/CSS-вёрстка. Next.js и другие изучаемые технологии не считаются подтверждёнными навыками.
- География и формат: удалёнка, гибрид и офис допускаются по всей России. Формат не указан — отдельная категория; он не считается автоматически удалёнкой. Вакансии с обязательным переездом или командировками исключаются.
- Международные вакансии из зарубежных источников допускаются только при явном подтверждении, что работодатель нанимает кандидатов, проживающих в России; слово worldwide/remote само по себе недостаточно.
- Фриланс — резервный канал: он показывается и обрабатывается только если после фильтров не найдено подходящих вакансий по трудоустройству. Платные ставки, кредиты и подписки не используются.
- Стажировки допускаются при зарплате 0–50 000 RUB/мес. включительно; отсутствие зарплаты у стажировки не блокирует её. Для обычных Junior / Junior+ — 50 000–70 000 RUB/мес. включительно; неизвестная зарплата отправляется на ручную проверку. Суммы выше верхней границы исключаются. Middle/Senior, Vue, Angular, Full Stack, React Native и Flutter исключаются. ASTON, PREAX и Edmagit исключены полностью.
- Обязательный SQL исключается; явно необязательный SQL («будет плюсом») не блокирует вакансию.
- QA-объявления могут появляться в отчётах, но автоотклики QA приостановлены.
- Полные требования некоторых источников недоступны из выдачи; поэтому соответствие недоступным требованиям нельзя подтвердить автоматически. Ранжирование не является гарантией соответствия.

## Черновики и отчёты

Сопроводительное письмо составляется на основе подтверждённых личных проектов с прямой ссылкой на код. Оно не утверждает коммерческий опыт и не приписывает навыки, которых нет в портфолио. Без явно настроенного резюме worker не отправляет отклики и не использует вымышленный профиль по умолчанию. Прямые обращения к рекрутерам и руководителям для оплачиваемых стажировок/практики и обычных Junior-вакансий пока формируются как черновики: автоматическая отправка и синхронизация ответов ещё не реализованы. Telegram используется для отчётов о фактическом результате. Бот считает найденные, отобранные, пропущенные и отправленные объявления и сообщает причины в сводке. Полные тексты писем не публикуются в логах GitHub Actions.

## Количество откликов

Установлен единый жёсткий лимит: **не более 10 подтверждённо отправленных откликов за календарный день суммарно по всем площадкам** — HeadHunter, Remote-job.ru, фриланс-платформам, email и другим поддерживаемым каналам. Это не 10 на каждый сайт и не отдельные 10 для вакансий плюс 10 для фриланса.

Счётчик общий: перед каждой отправкой worker проверяет число уже подтверждённых отправок за день в постоянной базе очереди; после статуса `SUBMITTED` увеличивает общий счётчик. Черновики, найденные вакансии, пропуски и не подтверждённые отправки в лимит не входят. Повторные отклики исключаются. Временные и недельные ограничения, если отдельно включены настройками, могут дополнительно уменьшить число отправок, но не увеличить общий дневной максимум.

## Запуск

`pip install -r requirements.txt`, затем `python worker.py`. GitHub Actions запускает плановый поиск в 08:00, 10:00, 12:00, 14:00 и 16:00 по Екатеринбургу (03:00, 05:00, 07:00, 09:00 и 11:00 UTC). Международные вакансии проходят только при прямом подтверждении, что кандидат, проживающий в России, может работать на эту компанию. Метки worldwide/anywhere/global/remote сами по себе недостаточны. Повторные отклики исключаются. Интеграции почты, Telegram и сайтов используют секреты окружения; их значения не должны попадать в репозиторий. Перед реальным использованием проверьте источники, фильтры, авторизацию и правила конкретной площадки.

Автор: [Alexander Kolomiets](https://github.com/Kolomiets94).




Условия вакансии проверяются отдельно от совпадения навыков: удалённый формат, явное разрешение на найм кандидатов из России и оплата стажировки получают статусы `confirmed`, `blocked` или `unknown`. Общая пометка `remote/worldwide` не считается доказательством найма из России; неизвестный статус не превращается в подтверждение. Эти поля добавляются к ATS-разбору как `ats_remote_status`, `ats_russia_eligibility` и `ats_paid_status`.

## ATS-оценка резюме

Job Hunter использует локальную объяснимую эвристику сопоставления текста резюме и вакансии. Это предварительный фильтр, а не копия закрытых алгоритмов СберПодбора/Huntflow и не гарантия решения работодателя. Отчёт показывает совпавшие и отсутствующие ключевые слова, явно обязательные пробелы, опыт и ограничения. Необязательные навыки не следует автоматически трактовать как отказ.

Для резюме поддерживаются TXT/MD, PDF и DOCX. Задайте RESUME_FILE на путь к файлу либо RESUME_TEXT для текста. Для PDF/DOCX используются pypdf и python-docx. Если файл отсутствует, не читается или не содержит извлекаемого текста, сопоставление и отправка с неподтверждённым профилем блокируются. Сканированные PDF без текстового слоя требуют OCR; OCR в текущей версии не включён. В резюме добавляются только фактически подтверждённые навыки и проекты.


## Обратная связь по результатам откликов

Журнал прямых обращений поддерживает фиксацию результата и одной категории причины отказа: несовпадение навыков, недостаточный опыт, географическое ограничение, право на работу, язык, зарплата, несовпадение роли, закрытая позиция или другая причина. Сохраняется только выбранная категория, а не текст переписки или персональные данные из ответа. Сводка показывает количество ответов, интервью, предложений и размеченных отказов. Эти наблюдения пока не меняют ATS-вес автоматически: сначала нужно накопить достаточную выборку и проверить качество разметки.


## Управление журналом через Telegram

Входящие команды доступны через защищённый webhook Render:

- Добавьте переменную окружения `TELEGRAM_WEBHOOK_SECRET` — случайный секрет из 32+ символов, допустимы буквы, цифры, `_` и `-`.
- Используйте уже настроенные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (или совместимые `BOT_TOKEN` и `CHAT_ID`). Команды принимаются только из чата с указанным ID.
- После деплоя зарегистрируйте webhook у Telegram вызовом `setWebhook`, передав URL `https://job-freelance-hunter.onrender.com/telegram/webhook` и тот же секрет в параметре `secret_token`. Не публикуйте токен и секрет в репозитории или переписке.
- В личном чате с ботом доступны `/help`, `/outreach` и `/set ID STATUS [REASON]`. Список показывает короткий ID, статус и компанию. Для отказа можно указать одну категорию причины, например `/set ab12cd34 REJECTED experience_gap`.
- Webhook проверяет Telegram secret header и ID разрешённого чата. Тексты входящих сообщений работодателей не сохраняются; команда только меняет статус и категорию причины в журнале.

До деплоя новой версии и настройки webhook команды не будут доступны в работающем Render-сервисе. Эта интеграция не отправляет отклики, письма или сообщения работодателям.


Для ручной фиксации результата доступны защищённые API-маршруты (заголовок Authorization: Bearer HUNTER_RUN_TOKEN):

- GET /outreach — список черновиков/обращений и агрегированный отчёт.
- POST /outreach/{outreach_id}/status — фиксация статуса. Для отказа можно передать одну категорию feedback_reason: skills_gap, experience_gap, location_restriction, work_authorization, language, salary, role_mismatch, position_filled или other.

Пример JSON тела: {"status":"REJECTED","feedback_reason":"experience_gap"}. Сырой текст ответа работодателя не сохраняется. API только обновляет журнал и не отправляет сообщений.
